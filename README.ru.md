# aw-agent-time

Локальный учёт времени при работе с AI-агентами поверх ActivityWatch.

- **Layer 1:** активность человека за компьютером и распределение по проектам.
- **Layer 2:** взаимодействие с Claude Code/Codex по локальным JSONL-логам.
- **Layer 2.5:** автономное время агентов: автономные сессии из индекса (`codex exec`, сабагенты Codex, сессии в worktree); task-runner — необязательное обогащение.

**Слои пересекаются — их нельзя складывать в рабочие часы человека.** Автономные
задачи тоже могут идти параллельно. Все дневные отчёты, включая `--today`, используют
**сутки UTC**, а не локальный часовой пояс.

## Установка примерно за 10 минут

Нужны macOS, Homebrew и Python **3.11+**. Скрипты используют стандартную библиотеку
Python. ActivityWatch устанавливается отдельно; tmux и aw-watcher-input необязательны.
На новом компьютере загрузки и выдача разрешений могут занять больше времени.

```bash
git clone https://github.com/OXI-717/aw-agent-time.git
cd aw-agent-time
python3 --version
python3 -m venv .venv
source .venv/bin/activate
bash install.sh
cp config.example.toml config.toml
```

Если `python3` старее 3.11, создай окружение поддерживаемым интерпретатором.
Установщик открывает ActivityWatch и сохраняет существующие настройки и службы.
Выдай запрошенные разрешения в System Settings → Privacy & Security и проверь свежие
события на <http://localhost:5600>.

Скопируй `categories.example.json` в приватный `categories.json`, замени примеры
своими правилами и укажи `paths.categories_file = "categories.json"` в конфиге.
Настрой пути источников. Для файлов отчётов можно задать `paths.obsidian_folder`;
Obsidian для этого не нужен. Конфиг, категории, логи и индекс исключены из Git.

```bash
python3 scripts/lint_categories.py --no-data
python3 scripts/jsonl_indexer.py
python3 scripts/aggregate.py --today --no-obsidian
```

Индексатор сначала обновляет локальный индекс AI-сессий. Агрегация запускает сборщики, заменяет вычисленные дневные buckets и печатает
отчёт. Исходные события watchers не изменяются. Layer 2.5 работает без оркестратора:
берёт интервалы активности автономных сессий из индекса (`codex exec`, сабагенты Codex,
любые сессии Claude Code/Codex внутри `.task-runner/worktrees/`). Фоновые запуски
`claude -p` пока не отличить от интерактивных SDK-сессий; OpenCode, OpenClaw, Cursor и
Gemini пока не индексируются. Данные совместимого task-runner, если есть, добавляют
номера задач и итоги; пути проектов задаются в `paths.layer25_project_roots`.

Чтение существующих buckets без повторного сбора и записи файлов:

```bash
python3 scripts/aggregate.py --date 2026-09-18 --skip-trackers --no-obsidian
```

Для сохранения `time-YYYY-MM-DD.md` задай папку отчётов, создай её родительский каталог
и убери `--no-obsidian`. После смены суток UTC плановый запуск завершает вчерашний отчёт.

## Конфиг и автоматический запуск

Все параметры — в [config.example.toml](config.example.toml). Приоритет: defaults →
`config.toml` → поддерживаемые env-переменные `AW_TRACKER_CONFIG`,
`AW_TRACKER_BUCKET_PREFIX`, `AW_TRACKER_CLIENT_NAME`, `AW_TRACKER_CATEGORIES_FILE`.
Относительные пути считаются от конфига. Явно выбранный отсутствующий конфиг — ошибка.
При переносе существующей установки сохрани старые bucket/event/client prefixes,
пути и группировки в приватном конфиге.

```bash
bash install.sh --render-launchd
```

Команда только создаёт файлы в `state/launchd/`: агрегация каждые 30 минут и обновление
индекса/Layer 1 каждые 5 минут. В `launchd.python` лучше указать абсолютный путь Python
из `.venv`. После проверки установи выбранные jobs через `launchctl bootstrap` —
пример есть в [английском README](README.md#optional-background-jobs).
Установи также fast job, чтобы индекс продолжал обновляться. Существующие отличающиеся
plist не перезаписываются.

`--include-tmux` добавляет опциональный watcher фокусной панели; нужен tmux.
`--include-input` требует установленного aw-watcher-input и разрешений macOS.
Стандартными window/AFK watchers управляет само приложение ActivityWatch.

## Ограничения и приватность

Фокус tmux определяется по наиболее активному клиенту. Несколько attached-клиентов,
устаревшие пути и общий заголовок окна (например, Orca) делают распределение неточным.
Отчёт отмечает inferred/ambiguous интервалы. Это оценка активности, не аудит присутствия
или биллинга. Review grace ограничен восемью минутами; настройки AFK watcher дополнительно
влияют на учитываемое время. Форматы AI-логов меняются между версиями.

[Синтетический пример отчёта](docs/example-report.md). Локальные логи и события могут
содержать запросы, заголовки, пути и имена клиентов — перед публикацией отчёта проверь
его содержимое. Облачная учётная запись скриптам не нужна.

## Проверка и экспорт

```bash
python3 -m pip install -r requirements-dev.txt
python3 -m pytest -q tests
bash scripts/export-public.sh ../aw-agent-time-public
```

Экспорт использует точный список `public-files.txt`, отвергает симлинки/бинарные файлы
и существующую папку назначения. Приватные настройки, данные и история Git не копируются.
Создаётся новая история из одного коммита с публичной identity. Перед push нужны просмотр
всех файлов, скан секретов/личных данных и тесты в экспортированной копии.
